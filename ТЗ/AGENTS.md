
# Правила разработки проекта

## 1. Проект
Локальная Windows-система учёта товаров, складов и продаж для одного филиала.

- Главный ПК работает как сервер.
- Остальные компьютеры подключаются через браузер по локальной сети.
- Интернет для продаж не требуется.
- Один общий принтер чеков XP-Q80AS подключён к серверу.

## 2. Технологии
- Node.js + TypeScript.
- SQLite через better-sqlite3.
- Vitest для тестирования.
- SQL-миграции хранятся в migrations/.
- Структура: src/db/, src/core/, src/modules/, src/web/, tests/.

## 3. Главные правила
- Кассовых смен нет. Не создавать shifts и shift_id.
- Один филиал, складов может быть несколько.
- Начальный остаток равен нулю. Товары поступают через приход.
- Остатки рассчитываются по журналу stock_movements.
- Продажа в минус запрещена.
- Списание и исправления оформляются отдельными движениями.
- FIFO применяется при продаже.
- Себестоимость фиксируется в момент продажи.
- Деньги хранятся целыми тийинами.
- Количество хранится в тысячных долях.
- Не использовать float для денежных расчётов.

## 4. Корзины и пользователи
- У каждого кассира отдельный аккаунт.
- У кассира может быть только одна активная сессия.
- Новый вход отзывает предыдущую сессию.
- Обычные и отложенные корзины сохраняются в БД.
- Корзины привязаны к аккаунту и восстанавливаются после перезапуска.
- Корзины разных кассиров изолированы.

## 5. Склад и инвентаризация
- Инвентаризация бывает двух видов: выбранные товары или весь склад.
- На одном складе допускается только одна активная инвентаризация.
- Заблокированные товары нельзя продавать, принимать, возвращать, списывать или перемещать.
- Блокировки должны сохраняться после перезапуска.
- После фиксации результатов блокировка снимается.
- Право проведения инвентаризации: stocktake.

## 6. Продажи и деньги
- Оплата долга распределяется по конкретным чекам.
- Возврат оформляется по исходному чеку.
- Есть внесение и изъятие наличных, расходы и инкассация.
- Одна общая физическая касса.
- Отчёты формируются по кассиру и периоду.
- Печать выполняется через серверную очередь print_jobs.
- Сбой принтера не отменяет продажу.

## 7. Безопасность и надёжность
- Все права проверяются сервером.
- Важные операции выполняются транзакциями.
- Журналы stock_movements, payments, debt_ledger, cash_ledger и audit_log нельзя редактировать или удалять.
- Ошибки исправляются встречными записями.
- Рабочую БД запрещено использовать для разработки и тестирования.
- Резервное копирование и восстановление должны тестироваться.

## 8. Работа с кодом
1. Перед изменениями изучить соответствующий раздел ТЗ и существующий код.
2. Выполнять только одну поставленную задачу за раз.
3. Не угадывать недостающие требования. При противоречиях задавать вопрос.
4. Новые изменения БД оформлять отдельными миграциями.
5. Не изменять уже применённые миграции.
6. Добавлять автоматические тесты для новой логики.
7. После изменений запускать npm test.
8. Интерфейс и чеки должны поддерживать русский и узбекский языки.
9. После каждого этапа сообщать изменённые файлы, результаты тестов и что проверить вручную.

npm run migrate
npm run dev
