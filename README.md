# Kassa: система учёта остатков, продаж и общей кассы

Локальная система для склада и магазина (ТЗ v2.0, файл `docs/TZ_v2.md`). Работает без интернета:
сервер и база SQLite на главном ПК, остальные ПК открывают веб-страницу по локальной сети.

**Этапы 1–9 реализованы; этап 9 ожидает ручной проверки.** Печать чеков на XP-Q80AS всё ещё нужно проверить на реальном принтере.

## 1. Что установить (один раз)

1. **Node.js 22 LTS**: https://nodejs.org (при установке оставьте галочку «Add to PATH»).
2. **Git**: https://git-scm.com
3. **VS Code** и расширения **GitHub Copilot** и **GitHub Copilot Chat** (VS Code предложит их сам, они в `.vscode/extensions.json`). Нужна учётная запись GitHub с подпиской Copilot.

## 2. Первый запуск

Откройте папку проекта в VS Code (File, Open Folder), затем терминал (Ctrl+`):

```
npm install
cp .env.example .env
npm test
npm run setup
npm run create-admin
npm start
```

Для первого запуска после `npm run setup` можно использовать скрипт из папки `start`: `start/start-windows.bat` на Windows или `./start/start-linux.sh` на Linux. Он создаст администратора и запустит сервер. Используйте его только один раз: при последующих запусках выполняйте `npm start`, так как создание администратора разрешено только для пустого списка пользователей.

Если в `.env` заданы `ADMIN` и `PASS`, а `DEFADMINLOGIN=true`, пропустите `npm run create-admin`: первый `npm start` создаст администратора.

- `npm test` запускает тесты на временных базах.
- `npm run setup` создаёт рабочую базу `data/kassa.db` (точка A, основной склад, способы оплаты).
- `npm run create-admin` интерактивно создаёт первого администратора; пароль вводится без отображения в терминале. Минимальная длина паролей — 5 символов.
- Если пароль администратора забыт, на главном ПК выполните `npm run reset-admin-password`; команда запросит логин, затем новый пароль с подтверждением, запишет аудит и отзовёт прежние сессии.
- `npm start` запускает веб-интерфейс на `http://<адрес-сервера>:3000`. По умолчанию сервер слушает все IPv4-интерфейсы, но отклоняет соединения не из локальной сети. На Linux разрешите порт только для LAN в настройках firewall (например, UFW).
- Администратор может посмотреть адреса для рабочих ПК во вкладке «Подключение ПК». Если показанный адрес недоступен, проверьте, что компьютеры в одной локальной сети, а Firewall разрешает порт сервера в частной сети.
- Для автосоздания администратора используйте `ADMIN`, `PASS` и `DEFADMINLOGIN` в `.env`. При `DEFADMINLOGIN=true` сервер создаёт пользователя только если нет активного администратора; существующие записи не меняются. Переключите значение на `false`, чтобы отключить автосоздание. В `.env.example` функция выключена; задайте собственный пароль длиной от 5 символов перед включением. Пароль `12345` легко угадать — не оставляйте его при доступе с других ПК.
- Для печати на Linux установите и настройте CUPS, подключите XP-Q80AS как raw ESC/POS-принтер и проверьте имя очереди командами `lpstat -v` и `lpstat -a`. Укажите точное имя очереди в `PRINTER_NAME`; по умолчанию используется растровый режим, чтобы сохранить кириллицу и узбекские буквы. Пользователь, запускающий сервер, должен иметь право печатать через CUPS. Если `PRINTER_NAME` пуст, продажи работают, а задания остаются в очереди; сервер выведет предупреждение. Проверьте русский и узбекский чеки, QR-код и обрезку на реальном принтере.
- В `.env` задан путь рабочей базы `DB_PATH`. **Никогда не подставляйте этот путь в тесты и не показывайте Copilot содержимое рабочей базы.**

После ручной проверки текущего этапа сделайте небольшой коммит:

```
git init
git add .
git commit -m "Этап 2: пользователи, сессии, справочники"
```

## 3. Как собирать остальное через Copilot

1. Откройте Copilot Chat (Ctrl+Alt+I). Внизу выберите режим **Agent** и модель посильнее (например, Claude Sonnet или GPT-5).
2. Для следующего этапа в поле чата введите `/` и выберите соответствующий запрос. Запросы лежат в `.github/prompts`.
3. Copilot читает правила проекта из `.github/copilot-instructions.md` автоматически и разделы ТЗ из `docs/TZ_v2.md` по ссылкам в запросе.
4. Дождитесь конца. Нажмите **Keep**, если изменения устраивают.
5. Проверьте сами: `npm test` и `npm run typecheck` должны быть зелёными. Если красные, напишите Copilot: «Тесты красные, исправь» и вставьте вывод.
6. Пройдите ручную проверку этапа (раздел 18 ТЗ) и сделайте коммит. **Только после этого** переходите к следующему этапу.

Далее: этап 10 — облако (необязательно), после ручной приёмки текущего этапа.

## 4. Правила безопасной работы с Copilot

- Один этап за раз. Не просите «сделай всё сразу».
- Если Copilot предлагает изменить `migrations/001_init.sql` или отключить триггеры защиты журналов, откажитесь: структура меняется только новой миграцией (002, 003...).
- Если Copilot написал код, но не запустил тесты, попросите: «Запусти npm test и покажи результат».
- Перед крупным этапом делайте коммит, чтобы можно было откатить: `git restore .` или `git reset --hard`.
- Печать на XP-Q80AS проверяется только на вашем ПК с принтером; Copilot этого сделать не может.

## 5. Что реализовано

- `migrations/001_init.sql`: все таблицы ТЗ v2: справочники, партии и движения, приход, списание, инвентаризация и блокировки, сессии, постоянные корзины, резервы, продажи, возвраты, аллокации FIFO, платежи, долги по чекам, аллокации оплаты долга, общая касса, кассовые операции, идемпотентность, аудит, очередь печати, очередь синхронизации. Кассовых смен нет.
- Защита на уровне БД: журналы нельзя править и удалять; не более одной активной инвентаризации на склад; блокировка товара на время инвентаризации; одна активная сессия на пользователя; одна текущая корзина на пользователя; в кассу попадают только наличные; остаток не уходит в минус.
- `src/core`: деньги в тийинах, количество в тысячных, UUID v7, номера документов без пропусков, транзакции, аудит.
- `src/db`: безопасное подключение (WAL, synchronous=FULL, foreign_keys) и миграции с проверкой контрольных сумм.
- Этап 2: Argon2id-аутентификация, одна активная сессия на пользователя, серверные сроки 12 ч / 2 ч, серверная проверка прав, аудит, API справочников и минимальные страницы входа, товаров, остатков и пользователей. Карточка товара содержит артикул, одно название, единицу учёта и цену продажи; пользовательские единицы доступны всем ПК.
- Этап 3: приход с транзакционным созданием партий и движений, запрет сторно при неполном восстановлении партий, FIFO-списание, пересчёт/сверка кэшей и страницы приходов, остатков и движений. Пока в одном документе нельзя указывать один товар несколькими строками; при разных закупочных ценах используйте отдельные документы до утверждения связи строки прихода с партией.
- Этап 4: чистый модуль расчёта цен и скидок без доступа к БД. Одинаковые товары объединяются; из подходящих ценовых правил выбирается самая низкая цена, скидки проверяются по правам и лимитам, сумма распределения сходится по строкам. Продажа ниже себестоимости запрещена без исключений.
- Этап 5: постоянная корзина кассира и экран продаж; серверная проверка цен и FIFO; смешанная оплата, долг по чеку и защита продажи от повторного запроса.
- Этап 6: список открытых долгов по чекам, распределение оплат от старых чеков к новым, администраторское частичное/полное прощение с причиной; общая касса, денежные операции, встречное сторно и журнал наличных. Кассовых смен нет.
- Этап 7: Linux/CUPS-драйвер ESC/POS, последовательная очередь, растровая печать RU/UZ с QR и автообрезкой, копии с подтверждением uncertain, снимок чека в момент продажи и настройки профиля печати.
- Этап 8: возвраты с восстановлением исходных партий, зачётом долга и возвратными чеками; FIFO-списания; выборочная и полная инвентаризация с блокировками и атомарным завершением; отложенные корзины, резервы, истечение и устранение дефицита резервов.
- Этап 9: 22 отчёта с фильтрами и CSV для Excel, права на себестоимость, ежедневные и ручные проверенные копии с хранением 30 дней, безопасное восстановление в новый файл, RU/UZ-переводы и инструкция NSSM для службы Windows.
- Драйвер передаёт raw ESC/POS в Linux CUPS (`lp`), чтобы не зависеть от native USB-модуля Node.js; растровый текст формируется `@napi-rs/canvas`, QR — `qrcode`, текстовый русский режим — CP866 через `iconv-lite`. Статус «Передан принтеру» означает, что CUPS принял задание; физический выход чека подтверждается проверкой владельца.
- `migrations/002_print_receipts.sql` добавляет язык и сохранённый снимок чека к очереди, не меняя применённую `001_init.sql`.
- `migrations/003_return_batch_allocations.sql` связывает возвратные движения с исходными FIFO-распределениями, не меняя применённую `001_init.sql`.

## 6. Отчёты, копии и запуск службой Windows

- Отчёты находятся на вкладке «Отчёты и копии». Даты считаются по Ташкенту; доступные фильтры меняются вместе с выбранным отчётом. Выгрузка — CSV с разделителем `;`, откройте файл в Excel. При выборе более 10 000 строк уточните фильтры: неполный отчёт не экспортируется.
- Укажите `BACKUP_DIR` в `.env` на другом физическом диске, например `E:\ERP-Backups` или `/mnt/backup-disk/ERP`. Сервер создаёт копию ежедневно после 02:00 по Ташкенту; администратор может запустить копию кнопкой. После создания выполняются `integrity_check` и сверка остатков с журналом. Старые копии удаляются после 30 дней.
- Перед обновлением остановите службу, создайте проверенную копию, затем обновите файлы программы и зависимости. Выполните `npm run migrate` и запустите службу снова. Не удаляйте `.env` или каталог рабочей базы при замене файлов.
- Чтобы проверить восстановление, используйте отдельное имя файла, например:

  ```
  npm run restore-backup -- "E:\ERP-Backups\kassa-backup-....sqlite" "E:\ERP-Test\restore-check.sqlite"
  ```

  Команда откажется писать в путь `DB_PATH` и не заменяет существующий файл. Не подменяйте рабочую базу проверочной копией.

### Установка Windows-службы через NSSM

1. Установите Node.js 22 LTS, разверните проект в постоянном каталоге (например, `C:\ERP`), выполните `npm install`, настройте `.env` и проверьте запуск `npm start` в терминале.
2. Установите NSSM из официального дистрибутива и запустите терминал от имени администратора. Командой `nssm install KassaERP` откройте настройки новой службы:
   - **Application path:** `C:\Windows\System32\cmd.exe`
   - **Startup directory:** каталог проекта, например `C:\ERP`
   - **Arguments:** `/d /s /c "call npm.cmd start"`
3. Во вкладке **Log on** выберите отдельную ограниченную учётную запись Windows. Дайте ей доступ на чтение к коду и `.env`, запись к рабочей базе и каталогу `BACKUP_DIR`. В **I/O** задайте файлы журналов вне каталога проекта.
4. Ограничьте входящий порт приложения в Windows Firewall профилем «Частная сеть» и разрешите доступ только локальной сети. Запустите службу: `nssm start KassaERP`; остановка — `nssm stop KassaERP`.
5. Для обновления остановите службу, выполните `npm run backup`, обновите код, `npm install`, `npm run migrate`, затем запустите службу. Сначала проверьте версию на отдельной копии данных.

**Ограничение печати:** текущий драйвер чеков вызывает Linux-команду CUPS `lp`. Windows-служба запускает сервер, но сама по себе не обеспечивает печать на XP-Q80AS в Windows. Не включайте печать на Windows, пока для этого ПК не будет настроен совместимый драйвер; продажи при этом остаются сохранёнными, а ошибка печати не должна отменять продажу.

## 7. Заметные решения при переносе ТЗ в схему

- В `stock_movements` нет поля `synced_at`: журнал неизменяем, статус отправки в облако хранится в `sync_outbox`.
- Проценты хранятся в базисных пунктах (5% = 500), поэтому поля `discount_bp` и `percent_bp`, а не `discount_pct`.
- Зачёт долга при возврате записывается как `DEBT_PAY` со ссылкой `return_id`, новых типов долга не добавлено.
- В `payments` добавлены `purpose` (sale, return, debt_payment) и `tendered` (принято от клиента, для сдачи на чеке).
- Партия `opening` (начальный остаток) запрещена: остаток появляется только из прихода или излишка инвентаризации.
- Статусы очереди печати расширены до `printing` и `uncertain` (раздел 7.8 ТЗ).
- Файл `package-lock.json` отключён (`.npmrc`: `package-lock=false`), версии зафиксированы точно в `package.json`. Причина: с lock-файлом npm пытается собрать SQLite из исходников и просит Visual Studio Build Tools; без него ставится готовая сборка. Используйте `npm install`, не `npm ci`. Если `npm install` всё же просит компилятор, проверьте, что установлен Node.js 22 или новее (`node -v`).
